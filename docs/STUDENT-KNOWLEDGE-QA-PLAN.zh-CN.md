## 1. 目标与使用流程

将当前综合 AI 平台精简为面向学生的知识库问答系统，只保留四类业务：

1. 对话：学生登录后提问、检索知识库、查看回答与来源、管理自己的对话记录。
2. 知识库：管理员导入教学资料、维护知识库、处理解析和向量索引。
3. 上游与模型配置：管理员配置服务地址、密钥、聊天模型、模型路由及默认模型。
4. 用户管理：管理员创建和批量导入学生账号，维护账号状态、密码和必要授权。

保留浏览器和桌面客户端两种访问方式。学生下载本分支对应的客户端，填入管理员部署的网址，使用导入的账号登录；资料、索引和对话保存在服务器。

完整业务流程：

```text
管理员配置上游及聊天模型
  -> 在知识库设置中配置文本解析、Embedding 和检索参数
  -> 上传教学资料，等待解析及索引就绪
  -> 发布知识库，设置默认模型和默认知识库范围
  -> 批量导入学生账号
  -> 学生通过网页或客户端登录
  -> 发起问题，服务端校验权限并检索教学资料
  -> 返回流式回答及可追溯来源
```

Embedding 是检索所需的向量化能力，与生成回答的聊天模型用途不同。仅配置聊天模型不能视为完成知识库配置。本文不包含免费服务推荐或价格比较。

## 2. 默认实施边界

以下是为执行明确的默认方案，不代表用户已经指定了全部细节。没有后续指示时按此实施，不自行扩展为教学管理平台。

| 项目 | 默认方案 |
| --- | --- |
| 角色 | 复用现有 `superadmin`、`admin`、`user`；普通用户即学生，不新增独立教师角色体系 |
| 账号来源 | 管理员创建或 CSV 批量导入，关闭开放注册 |
| 登录标识 | 复用用户名，可将符合现有规则的学号作为用户名；邮箱可选 |
| 知识库归属 | 管理员统一维护平台知识库；删除学生个人建库和资料上传能力 |
| 知识库可见范围 | 所有在用学生共享管理员启用的教学知识库；首版不做班级知识库隔离 |
| 默认检索 | 管理员配置默认知识库；学生新建对话即有检索范围，不要求先手动选择 |
| 模型使用 | 管理员配置默认聊天模型；单模型时简化选择器，多模型仍按现有授权机制校验 |
| 功能形态 | 最终删除多余页面、API、业务实现、配置和依赖；开关关闭只允许作为过程状态 |
| 学生端 | 对话历史、知识库只读目录与来源、基本账号设置、客户端下载入口 |
| 管理端 | 知识库、上游、模型、用户；必要设置合并进这些模块 |
| 桌面端 | 保留远程服务器模式；本分支学生客户端移除本地免登录运行模式 |
| 商业化 | 无充值、套餐、订阅、余额门禁、计价或支付 |
| 安全与运维 | 保留认证、权限、密钥加密、限流、必要技术日志、健康检查与备份基础能力 |

适用条件：同一部署内的学生允许访问同一批教学知识库。若以后要求不同班级或课程相互隔离，必须新增知识库授权关系并覆盖检索、来源和文件访问，不能直接把当前平台知识库当作班级隔离实现。

| 原位置 | 目标位置 |
| --- | --- |
| 后台文件与检索设置 | 知识库模块的“处理与检索设置” |

- 长期用户记忆、历史消息语义召回及其专用向量任务；保留当前对话所需上下文截断或压缩。
- 图片和视频生成、编辑、媒体生成任务、相关收费及预览演示路由。
- 公告、营销展示、综合统计看板、独立日志分析页面、独立内容审核管理模块。
- 第三方身份源、SSO/OAuth、自助注册、邮件注册和无需保留的身份绑定流程。
- 学生私有上游、学生私有模型、个人知识库、个人文件中心和学生上传接口。
- 对话公开分享、匿名分享阅读、分享文件下载与克隆，避免产生新的公开资料访问路径。
- 对话项目工作区、项目级工具和技能绑定、收藏标签等非核心组织功能；已有会话迁为普通历史，不连带删除正文。

- 独立关于、运营、文件、登录配置等后台页面；所需少量设置迁入保留模块。
- 桌面本地免登录模式和捆绑 sidecar；远程接入、系统凭据存储、窗口及必要平台适配保留。

## 5. 关键行为设计

### 5.1 默认模型与默认知识库

- 管理员能设置一个可用聊天模型，以及一个或多个已启用的默认知识库。
- 优先复用现有设置存储；默认知识库使用稳定 ID，不把显示名称当主键。
- 新建学生对话时，服务端解析并保存生效的知识库范围；前端显示当前范围。
- 如允许学生选择范围，只能从服务端返回的已启用平台库中选择，空选择仍执行管理员默认策略。
- 首版学生问答要求知识库范围有效，不能通过省略 ID、传空数组或构造请求变为任意无知识库聊天。
- 发送、编辑重试和恢复生成时重新校验模型、账号、知识库状态；历史保存的 ID 不等于永久授权。
- 默认模型不可用、默认库为空、索引未就绪、检索服务不可用分别给出可理解的状态，不静默忽略知识库。
- 没有相关证据时明确表示“知识库中未找到相关依据”，不显示伪造引用；检索基础设施故障应返回可重试错误。
- 模型指令明确区分检索资料与系统指令，不执行资料片段中要求忽略权限或泄露配置的内容。
- 引用保存资料名称、片段标识及已有可定位信息；仅在解析器实际提供页码时显示页码。
- 历史来源不可用时显示已删除或不可访问，不重新生成虚假的出处。

### 5.2 学生名单导入

新增管理员专用 CSV 名单导入，使用结构化 CSV 解析器，复用现有用户校验和密码哈希流程。

```csv
username,displayName,email
s20260001,Student01,
s20260002,Student02,student02@example.edu
```

- 提供模板下载、UTF-8 与 BOM 处理、文件大小及行数限制、预览校验、正式导入和结果汇总。
- `username` 必填，`displayName` 与 `email` 可选；服从现有长度和唯一性约束，并在模板说明中体现。
- 固定创建 `user` 角色，不接受从 CSV 传入管理员权限、订阅、余额或上游密钥。
- 默认由服务端为新账号生成独立随机初始密码，一次性返回管理员下载；不采用全班相同密码。
- 支持无邮箱学生首次登录修改初始密码，不因保留旧邮件验证流程而卡住登录。
- 现有凭据已有 `MustResetPassword` 状态，复用并验证其服务端执行；完成前仅允许密码修改、必要会话和退出操作。
- 文件内用户名重复、已有用户名、邮箱冲突和非法行逐行报告；重复导入默认跳过已有用户，不覆盖密码、角色或历史。
- 明确事务语义：建议逐行原子创建用户、凭据及必要默认授权，允许其他有效行继续；结果必须可核对且重试不重复建号。
- 预览不能写入账号；正式导入重新校验，不能信任客户端预览结果。
- 初始密码仅用于一次性交付，不写入日志、审计详情或数据库明文；下载响应禁止缓存，导出单元格防 CSV 公式注入。
- 删除 OpenWebUI 导入页、DSN 输入、余额换算、后端数据库读取器及专用契约；共享用户创建代码保留。

### 5.3 学生权限与文件来源访问

学生只能管理自己的对话，读取启用的平台知识库和被允许展示的来源。管理员接口不能仅依赖前端隐藏。

- 所有管理写入接口保留管理员检查；学生不能修改角色、上游、模型、默认库或资料。
- 学生个人建库、上传、私有上游等 API 最终不注册，构造请求也不可使用。
- 检索候选范围、缓存、来源预览和文件内容接口使用同一可见性规则；缓存键覆盖知识库范围及版本，防止返回已禁用资料。
- 学生来源展示默认提供已命中片段与可定位信息，不以隐藏按钮替代原文件下载权限。
- 若移除完整文件预览，必须同步收紧现有内容接口；若保留，则明确这意味着学生可以获取该平台资料内容。
- 禁用学生账号后，刷新和现存请求的授权按统一机制失效；不能仅阻止下一次密码登录。
- 删除或禁用知识库后，新的问答不可继续检索该库；关联资料安全清理，不能误删其他库仍引用的文件。
- 上游及向量服务密钥只保存在服务端，返回前端的设置必须脱敏；保留出站地址安全检查。
- 保留请求频率、并发和生成长度限制，删除计费不等于删除资源限制。

### 5.4 桌面客户端接入与发布

- 保留 `apps/desktop`，继续复用 `apps/web` 静态产物；首次进入远程地址输入，再进入服务器登录页。
- 默认允许学生手填网址；管理员分发时可预填，但不默认锁死为某个未知域名。
- 沿用现有 origin 级服务器地址约束，例如 `https://chat.example.edu`；不承诺支持子路径部署，除非另行验证和实现。
- Rust 侧保留刷新令牌存储与续期，不把长期凭据移到网页 `localStorage`。
- 保留跨服务器凭据隔离、退出清理、重启恢复、网络错误和服务器能力读取。
- 使用有效 HTTPS 证书；后端 CORS 显式允许实际使用的 Tauri WebView Origin，不能改为任意来源通配。
- 学生不需要本地模型、知识库或 Go 服务；移除本地模式 UI 后，同步删除 Rust 本地会话分支、sidecar 启动、`externalBin`、构建脚本调用和相关 CI 步骤。
- 整理 `session.rs`、`tabs.rs`、`lib.rs` 等共享本地/远程逻辑时保留远程会话安全和窗口权限。
- Windows 现有策略支持禁用本地模式，可用于迁移过渡；策略禁用不等于最终完成本地代码与构建依赖删除。
- 当前自动更新源指向原项目，首版默认关闭自动下载和安装，不允许静默更新回完整版本；以后有本分支的受控签名发布渠道再配置更新。
- 新增本分支构建产物标识，核对应用 identifier、签名、安装升级和凭据命名空间，避免与原版混淆。
- 先验收实际使用的 Windows 安装包，其他系统沿用构建结构但仅对测试过的平台声明可用。

完成标准：网页和桌面共用页面没有死链、残留弹窗、持续 404 请求或已删功能按钮。

### 阶段 4：解耦后端并删除多余业务

按依赖关系实施，通常先处理旁路模块，再处理与主调用链耦合的计费、工具和记忆。

> 进度：公告、提示词预设、公开分享、交互式 UI 组件库、长期记忆与历史语义召回、工具市场与 MCP（含后端运行时、前端入口、模型原生工具配置、国际化与文档）、媒体生成（图像与视频生成/编辑适配器、媒体任务与制品下载、管理端媒体协议与预设、前端流式媒体通道、专属错误码与文案、媒体预览演示路由、共享媒体契约字段与文档配图）已删除并通过构建检查。剩余阶段 4 范围：临时对话与导出、对话项目、计费（保留轻量 token 用量）、Skills，以及拒绝旧请求中启用上述功能的字段。
> 媒体生成切片验证：后端 `go test ./...`（仅 3 项既有 Windows 环境失败）、`go vet ./...` 与标记构建通过；网页端 `tsc --noEmit`、`biome lint .`、`check-architecture.mjs` 通过；`packages/api-contract` 生成结果与实现一致。历史消息中的既有媒体附件与工具结果仍按只读展示处理，不再提供生成入口。

- [ ] 删除多余 HTTP 路由和 handler，收紧资料读取及来源访问边界。
- [ ] 从主装配及 auth、channel、admin、conversation 拆除订阅解析、余额校验、费用预占和结算。
- [ ] 模型可见性只由启用状态及有效授权决定，不依赖价格或计费账户存在。

完成标准：后端不再注册和执行已删业务，不依靠空实现计费服务、全局放行权限或长期 feature flag 维持运行。

## 8. 验证安排

本节命令是执行模型的检查候选，来自现有仓库脚本，本次未执行。重构后需根据保留的脚本及 CI 校正，不能仅凭命令示例声称测试通过。

用户明确要求：**凡涉及启动命令的 Shell 实测，均在 Windows Terminal 中执行。** 使用其 PowerShell 配置文件记录目录、命令、输出及访问结果，不将其他后台 Shell 的启动视为已满足该要求。

仓库根目录的检查候选：

```powershell
pnpm --filter @deeix/web check
pnpm --filter @deeix/web build
pnpm --filter @deeix/core check
pnpm --filter @deeix/core test
pnpm api:generate
pnpm api:check
```

在 `backend` 目录执行后端检查候选：

```powershell
go test ./...
go build ./...
```

后端现有质量检查通过 `make lint` 调用 Bash 脚本，具体要求以 `backend/scripts/check-go-quality.sh` 和 CI 为准。Windows 环境如缺少所需工具，记录阻塞并在 Windows Terminal 选择已安装的兼容工具链，不假定 PowerShell 可直接执行所有 Makefile 命令。

客户端在重构打包脚本后，从根目录执行：

```powershell
pnpm --filter @deeix/desktop check
pnpm --filter @deeix/desktop test
pnpm --filter @deeix/desktop build
```

启动候选为根目录的 `pnpm dev:api`、`pnpm dev:web`、`pnpm dev:desktop`；其中 API 脚本当前依赖 Make，客户端脚本当前依赖 sidecar，必须在完成对应调整后实测。启动网页及 API 时应分别在 Windows Terminal 标签页运行，记录实际端口，端口冲突时使用其他可用端口。

测试重点应覆盖变更风险，不为已删除业务保留镜像测试：

- 解析、向量化、检索、引用与共享文件清理。
- 默认知识库、旧 ID、禁用资料、检索缓存及伪造请求边界。
- CSV 预览、重复导入、非法行、并发唯一性、初始密码和首次改密。
- 两个学生间对话隔离、学生对后台 API 的越权尝试、禁用账号及会话撤销。
- 删除计费后，无余额、无套餐账号仍可使用合法模型。
- 浏览器与 Windows 安装包实测登录、流式回答、续期、退出及来源阅读。
- 空库部署、存量迁移和备份恢复。

不预设“支持多少学生”或固定延迟指标。取得预期并发和硬件参数后，用真实资料集和相应并发压测，报告测试条件、成功率、检索及生成延迟，再制定容量结论。

## 9. 最终验收清单

- [ ] 管理员后台仅有知识库、上游、模型、用户四类业务，必要设置已合并。
- [ ] 学生不能注册、上传资料、创建个人库、配置私有上游或访问后台管理功能。

- [ ] 单个默认聊天模型和有效向量化配置下，新学生登录即可检索默认教学知识库。
- [ ] 回答有可核对来源，缺少证据时说明未找到依据，基础设施故障不会伪装为正常检索成功。
- [ ] 学生之间的对话、凭据及未授权资料不互相泄露，禁用状态对续期和接口有效。
- [ ] 管理员密钥在网页、客户端、源码产物和日志中均不可读取。
- [ ] 计费、工具、记忆、媒体生成、作品库、分享、公告等已删功能没有可调用的业务 API 或运行任务。

- [ ] 删除或禁用知识库会影响后续检索，历史来源展示有明确失效状态。
- [ ] 学生客户端填写服务器网址后可登录使用；没有本地免登录入口或 sidecar 打包依赖。
- [ ] 客户端不会自动更新回原项目完整版本，安装包内前端来自本分支当前构建。

- [ ] 空库和存量迁移均验证，必要的启动实测在 Windows Terminal 完成。
- [ ] 有实际部署与备份恢复记录，交付明确列出测试过的配置和仍存的限制。
